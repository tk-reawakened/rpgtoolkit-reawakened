# TK Reawakened Website

The official site at `tk-reawakened.com` introduces TK Reawakened to people who want to learn to make RPGs. It helps them get the software, see what they can make, and meet other beginners who are learning and building together. Returning creators can find the right release for their old projects and share what they know. Players and creators can discover games, share new work, and help preserve Toolkit history.

## Proposed launch

The home page explains what TK Reawakened is, shows what someone can do with it, and makes the software easy to get. It points directly to the first guide under Create or Docs, where the steps live. It also features games from the collection and shows how to contribute another game. Give extensions and asset packs visible placement on the home page and a direct route to the Vault. Introduce the people making games, tools and resources together. The [16-bit workshop proposal](addendum.md#16-bit-workshop) records one navigation and visual direction to test.

| Area | What someone can do |
| --- | --- |
| Download | Find the current release by platform and role, such as authoring or playing, and see requirements, install/open instructions, release notes and the matching docs. Clearly identify preview builds when available. |
| Docs | Search responsive, versioned guides. Start with a small game that works against the shipped build. Find RPGCode and editor reference, migration and troubleshooting guides, and links from the guide to tested examples. |
| Games and showcase | Find preserved Toolkit games, new releases and demos. Browse Work in Progress as a category of Games. A work-in-progress listing includes screenshots and a build visitors can play in the browser. Label catalogue entries by origin and availability. Start with one original example and a small set of approved entries. A “Contribute a game” route can take a link to a new project or a lead on a missing classic. Publish credited entries with permission, a short description and a play, archive or devlog link as appropriate. |
| The Vault | Find extensions, starter templates, asset packs and reusable RPGCode examples. Help beginners browse by what they want to make as well as by resource type. Show what each entry adds, supported releases, credit and licence, and how to install or use it. Feature resources a beginner can use with a guide. |
| Community | Meet other beginners, ask for help, share work, playtest, and contribute to the project or its guides. Offer a simple submission path for a link, screenshot or recipe. Publish a code of conduct, a report route, and a short explanation of how submissions are reviewed and credited. |

## Give people a reason to come back

Start with one small, time-boxed prompt and a host who will run it. A **one-room RPG** is a candidate once the first-game tutorial is verified. If the community opens before the editor ships, start with a sprite, map sketch or short story prompt that anyone can join. Ask participants to give one useful piece of feedback, with the host arranging a first response when a submission has none. Publish a recap with credited entries and link it back to the starter guide. Spotlight work and feedback from the next round on the home page if someone can sustain the cadence. For example, an unfinished level can ask whether players notice its first exit.

Both rpgtoolkit.com and Toolkit Zone gave people a way into the community from the same site where they got the software. In 2001, rpgtoolkit.com put downloads and games beside the Game Dev section, a community site directory and message boards. In January 2007, Toolkit Zone linked its lead sprite challenge directly to the forum and paired it with game releases, screenshots and a featured game seeking feedback. The Games area distinguished releases from progress posts and images. The Library made articles discoverable by topic and highlighted recent contributions. Use those patterns to shape the new navigation, showcase and prompts, and publish new content or creator-approved archive highlights.

A work-in-progress page shows screenshots, links to a browser-playable build and tells visitors what the creator would like them to try. It links directly to the game’s topic in Community, where visitors can follow updates or respond to that request. That topic links back to the game. Featured releases and community prompts can use the same pattern. Readers can follow the conversation where they found the work, and the forum holds the replies and moderation. See the [forum integration proposal](../epic-documentation-website/discovery/hosting-options.md#forum-integration).

## What to prove first

- From the home page, a first-time visitor can explain what the product does, find the right build and reach the first-room tutorial. A returning creator can find the migration prerequisites and understand what their old project can import.
- A visitor can identify a preserved game and a newly made project, see what is playable, and find where to contribute a game. A reviewer can publish an approved submission with consent and credit, and a visitor can open a work in progress in Games, see screenshots, launch its build in the browser, follow its link to the specific Community topic, and return to the same game page.
- A beginner finds a resource from the home page or a guide, chooses the version that works with their build, and uses it in a small project.
- The first prompt produces a dated public recap and evidence that makers received feedback. Review submissions, replies and repeat participation before deciding how often to run it.

## Keeping the site open

The proposed funding principle keeps the engine, editor, documentation, public game playback and community archive free. Start by considering a low-key Support link with actual operating costs and optional links to creators’ own support pages. The [funding proposal](addendum.md#funding-the-project) records hosted service and creator pack options for later review.

## Open decisions

- Pick the home for help and feedback with its moderators. Name the launch owner for submission review, reports, the prompt and its recap. Test the flow with a newcomer and a returning creator.
- Choose the website repository and [hosting for `tk-reawakened.com`](../epic-documentation-website/discovery/hosting-options.md). Decide where public guides are authored and how product releases provide builds, version data and verification inputs. The website is expected to have its own repository.
- Decide how the public games catalogue presents the [preservation corpus](https://tk-reawakened.github.io/corpus/) alongside new projects, and who reviews new game submissions and recovery leads. Choose the first featured Vault entries from resources with clear permission, verified compatibility and a beginner-friendly use case.
- Decide whether durable discussions belong on an existing service or a separately hosted forum. Revisit built-in site accounts, file uploads and game hosting after seeing how people use the curated showcase and feedback channel.
