# Hosting options for tk-reawakened.com

Compared on 2026-11-14. The owner has the domain. The DNS check returned Porkbun nameservers and Porkbun mail-forwarding MX records. The host choice is open.

Build the first site as a portable static deployment from the website repository. The build includes the landing pages, versioned docs and search index, and the Games and Vault catalogues. Its download page points to the official release artifacts. Publish a representative preview before connecting the production domain.

| Option | Fit for launch | Tradeoff |
| --- | --- | --- |
| GitHub Pages | A GitHub Actions workflow can publish the entire static site from the public website repository when catalogue changes merge. It can use the existing DNS provider and link to a forum on another host. | Published site limit of 1 GB and a soft bandwidth limit of 100 GB per month. [Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) · [Custom domains](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site) |
| Cloudflare Workers Static Assets | Static requests are free and unlimited. Cloudflare also offers Git builds and previews. Cloudflare Pages supports Git-backed static deployments as another option. | Serving the apex directly requires a Cloudflare zone. A DNS move from Porkbun would need to carry over and verify the existing mail records. Workers limits a single static file to 25 MiB. [Static asset billing](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/) · [Workers custom domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/) · [Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/) · [Pages domains](https://developers.cloudflare.com/pages/configuration/custom-domains/) |
| Netlify | Deploy previews and built-in forms could help with submissions. The apex can use external DNS. | Production deploys and traffic consume credits. The free plan has a hard monthly credit cap. [Netlify plans](https://docs.netlify.com/manage/accounts-and-billing/billing/billing-for-credit-based-plans/credit-based-pricing-plans/) · [External DNS](https://docs.netlify.com/manage/domains/configure-domains/configure-external-dns/) |
| AWS Amplify Hosting | Managed hosting with support for external DNS. A fit if the project already wants to operate the site through an AWS account. | Metered builds, storage and data transfer beyond applicable allowances. The external DNS setup needs an apex alias record. [Amplify pricing](https://aws.amazon.com/amplify/pricing/) · [External DNS](https://docs.aws.amazon.com/amplify/latest/userguide/to-add-a-custom-domain-managed-by-a-third-party-dns-provider.html) |

**Research task.** [Spike 17.1](../spike-compare-low-cost-website-hosting.md) compares provider costs and limits, then runs the same preview and catalogue publishing proof on the two leading candidates. GitHub Pages can serve the entire static site and both catalogues. Cloudflare Pages offers free static delivery and pull request previews. Netlify is a candidate if its deployment workflow or forms justify the usage model. Use the [initiative’s Modern Web Guidance requirement](../../initiative-tk-reawakened-website.md#web-implementation-guidance) on the preview. Test versioned doc links, search, a release link, a representative showcase entry and a rollback before choosing the production host. Cloudflare documents free static requests and 500 monthly builds on the Pages Free plan. [Pages pricing](https://developers.cloudflare.com/pages/functions/pricing/) · [Pages limits](https://developers.cloudflare.com/pages/platform/limits/) · [Preview deployments](https://developers.cloudflare.com/pages/configuration/preview-deployments/)

The [moderated publishing proposal](../../brief-tk-reawakened-website/addendum.md#moderated-catalogue-publishing) uses a pull request to update catalogue data. After merge, the static build reads those entries and publishes the HTML. GitHub Pages can publish the build through GitHub Actions, and Cloudflare Pages can build it from the connected repository. A submission form or forum can handle intake for either host. The first publishing test should merge one game or Vault entry and confirm it appears on the deployed site. [GitHub Pages publishing](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) · [Cloudflare Pages Git integration](https://developers.cloudflare.com/pages/configuration/git-integration/)

Large downloads can come from published release artifacts or later use R2 if the Vault needs managed storage. R2 has zero internet egress fees and charges for storage and operations beyond its allowance. Price the workload before promising upload quotas or long-term hosting. Keep Porkbun as registrar if Cloudflare serves the apex. Plan the DNS cutover after preview acceptance and preserve the existing mail records. [R2 pricing](https://developers.cloudflare.com/r2/pricing/) · [Pages domains](https://developers.cloudflare.com/pages/configuration/custom-domains/)

Astro and Eleventy are candidate static generators. Keep framework and backend selection open until the preview. Evaluate Workers and D1 if an actual submission or forum integration needs a server-side endpoint. If a maintained self-hosted Flarum or Discourse instance is chosen, Cloudflare Tunnel is an option for the forum subdomain. The forum still needs its own moderation, backup and restore plan. [D1](https://developers.cloudflare.com/d1/) · [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/)

## Forum integration

GitHub Pages publishes HTML, CSS and JavaScript. A forum needs a service that handles sign-in, posts, persistence and moderation. The Community page can link to GitHub Discussions or to a standalone forum such as Discourse at `forum.tk-reawakened.com`. The website and forum can be hosted independently. An existing chat channel is another candidate for live conversation. Decide where durable help and playtest feedback should live and who moderates it before opening a new channel. [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) · [GitHub Discussions](https://docs.github.com/en/discussions/quickstart) · [Discourse](https://www.discourse.org/about)

Toolkit Zone’s archived forum credits phpBB and includes a forum for the sprite challenge promoted on the home page. An archived game page sends sign-in and profile links to the forum while displaying feedback on the game page itself. A Library article also links to forum sign-in and keeps its comment form on the article. Those captures show how connected the site and forum felt. They leave the underlying storage and session implementation open. [Forum index](https://web.archive.org/web/20061230231330/http://toolkitzone.com/forum/index.php) · [Game page](https://web.archive.org/web/20051218213035/http://toolkitzone.com/games.php?file=121) · [Library article](https://web.archive.org/web/20060612052748/http://toolkitzone.com/library.php?mode=read&doc=239)

The Work in Progress category lives in Games. Each work-in-progress page opens its specific Community topic for updates and the creator’s feedback request. The topic links back to the game. Featured releases and other selected content can use the same pattern. A prompt or release announcement has a topic of its own, and the first post links back to the permanent page. Docs can link to suitable help discussions with the release version in context. The forum owns accounts, replies and moderation.

1. **Start with one linked topic and a backlink.** Store its stable topic ID or URL with one showcase entry. Use the same topic if the showcase page moves or is rebuilt. Keep a direct link available for visitors using assistive technology or blocking embeds.
2. **Try an inline discussion on that page.** Discourse can embed an existing topic by ID, and its full-app mode supports replies through the embed. Test a guest reading, a signed-in playtester replying, and a moderator removing a reply. Check on mobile and confirm the direct link still works with the embed blocked. [Embedding existing topics](https://meta.discourse.org/t/embed-discourse-comments-on-another-website-via-javascript/31963) · [Discourse full-app mode](https://meta.discourse.org/t/embed-discourse-as-a-full-comment-system-on-your-site/399743)
3. **Bring selected forum activity onto the home page.** Start with a small list of curated topic links. If we automate it, use the forum’s public API or feed to update a small published list of approved topic titles and links. A failed refresh leaves the rest of the site and its discussion links usable. Keep any credentials in the build or a server-side integration. [Discourse API](https://docs.discourse.org/) · [GitHub Discussions API](https://docs.github.com/en/graphql/guides/using-the-graphql-api-for-discussions)

The proof is a playtester finding the game and its discussion, leaving a reply that appears in the same forum topic, and following the backlink to the game. The forum provider and ownership remain open.
