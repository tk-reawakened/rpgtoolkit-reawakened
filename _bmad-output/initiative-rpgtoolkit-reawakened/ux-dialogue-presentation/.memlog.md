topic: Dialogue presentation for RPG Toolkit Reawakened
updated: 2026-10-23T16:10
---


- (decision) The foundation preserves plain mwin(text) while allowing structured speaker metadata and startup-configurable presentation; it does not build a dialogue editor, branching graph, or dialogue asset format.
- (decision) A multi-line interaction is explicitly bracketed by begin/end commands around ordinary RPGCode flow; completion is not inferred from mwin followed by wait.
- (decision) Speaker names and portraits resolve from actor/character data where available; do not add a duplicate startup profile registry. Startup code configures presentation defaults.
- (decision) Per-line speaker metadata changes only displayed identity. The interaction scope owns the event actor and optional target; dialogue.completed carries {actorId, targetId, text}, with displayed lines joined in order by newlines.
- (decision) The user approved adding a portrait asset reference to the persisted actor contract now; legacy character profilePicture is the source where available, and actors without one show no portrait.
- (decision) Speaker presentation uses a compact portrait at the left of the existing fixed message window and a speaker name above the dialogue text; existing game-configured window appearance remains in control.
