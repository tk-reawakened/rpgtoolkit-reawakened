## 1. Scope restatement (sanity check)

**Outcome.** RPGCode 3.1 runs on an explicit step-machine VM whose entire state is plain JSON — parser, interpreter, functions, classes, includes, error handlers, cooperative threads, blocking by yielded status, source/target context and sandboxed file I/O. A three-tier pipeline (ADR 0004): distinct TK2 and TK3 dialect frontends → one Unified AST → a linear **Step IR** → the VM. TK2 commands live in a compat plugin; core built-ins register through the dogfooded `PluginDefinition`/`BuiltinSpec` contract (AD-8), which every domain epic uses. The epic's success signal is CAP-5's: `system.prg` and `start.prg` run to completion headlessly, every §9.11 built-in **name** resolves somewhere across epics, and a mid-script snapshot restored into a fresh VM finishes identically (G1).

**Done when** (6 checks, `epic-rpgcode-vm.md`): (1) `system.prg`/`start.prg` run headless with scripted input; (2) random-step snapshot → fresh VM → identical result and state hash, for every corpus program (G1); (3) board/persistent/item threads, sleep, wake, `tellThread`, blocking and `multiRun` behave as E-33/E-93; (4) errors report file and line and handlers/`resume` work as §9.8; (5) the language-only and pure built-ins work, domain built-ins register through the API and are owned by their epics; (6) the state shape, built-in contract and wake contract are exactly AD-7–AD-9.

**Boundaries.** The language, the VM, threads, and the built-in registration API plus the pure built-ins. World/render/audio/battle/menu/save built-ins belong to the epics that own those domains and only *register* here. Not the LSP/DAP (epic `rpgcode-tooling`, id 10). Pre-compiled `.prg` is out. Two seams this epic does **not** own are named explicitly below: `createEngine` (D12) and the loop/phase list (whose owner is `epic-board-rendering`).

**What the discovery changes about that picture** (`discovery/language-readiness.md`): the tokenizer is ready to write from §9.2, but read literally only **3 of 9 non-empty sample programs parse**; 12 doc fixes are needed first. The 10 files (227 statements, 325 of 747 lines comments) are a **weak** corpus for Done-when: 1 thread program, 0 error handlers, no object ever created, no by-ref user parameter, no multi-statement inline code. Synthetic programs are required for almost every item, and 19 of the 26 distinct domain built-ins the corpus calls must exist as test doubles before `start.prg` can complete.

**What the ownership audit adds** (`/tmp/epic-3-foundations-audit.md`): three foundations the epic's entries treated as existing have **no owner anywhere** — `core/fmath` (row 1), the VM-side breakpoint/pause hook (row 13) and the `Logger` port (row 3) — and `createEngine` has three claimants (row 14). All four are now assigned: `core/fmath` gets its own early entry, the breakpoint hook and `Logger` join existing entries, and `createEngine` is explicitly **not** this epic's (D12).

**Tracer bullet.** Entry 2, the thinnest path through every layer the epic names (`parser → Step IR → VM → built-in registration → snapshot/restore → harness`), plus one AD-9 yield so the wait seam is proven early.
