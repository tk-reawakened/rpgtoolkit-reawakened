# Scenario coverage — connected editors proposal

Each row is a proposed interaction, not an observed success, implemented capability or promise. The F identifiers point to [engagement user flows](../research-editor-ux-for-beginners/engagement-user-flows.md); guard refers to the [creator rehearsal](../research-editor-ux-for-beginners/creator-journey-workspace-rehearsal.md). Concepts dependent on a model, host, runner or provider are conditional. See [EXPERIENCE.md](EXPERIENCE.md) for common selection, save, undo, scope, context, accessibility and recovery rules.

| Scenario | Surface | Entry and proposed action | Observable intended outcome / boundary | F reference |
|---|---|---|---|---|
| SC-01 Premise | [Workspace](wireframes.html#workspace), [Events](wireframes.html#events) | Choose blank project, write a note or open an available optional conversation; mark assumptions and unresolved characters/places. | Creator chooses one small next step without unsolicited whole-game generation; notes need not become a new story-document format. | F-01, F-11, guard |
| SC-02 Story first | [Events](wireframes.html#events), [Board](wireframes.html#board) | Draft guard dialogue/choice before making a board; connect existing participants or leave unresolved; return after staging. | Unfinished writing and authorial intent survive; branch outcomes are not silently invented. | F-11, guard |
| SC-03 First playable | [Workspace](wireframes.html#workspace), [Settings](wireframes.html#settings) | Choose blank or explained template; inspect created content, make one deliberate change, save and Play from game start. | Creator sees the change in a real supported run without having to edit a main file; missing runner/content is disclosed. | F-01, F-13 |
| SC-04 Return | [Workspace](wireframes.html#workspace), [Settings](wireframes.html#settings) | Open existing project, browse Game/Files, inspect effective startup and Problems/unresolved links. | Locate what is actually used without rewriting originals or treating remembered intent as fact. | F-13, F-01 |
| SC-05 Change direction | [Artwork](wireframes.html#artwork), [Board](wireframes.html#board) | Compare old/new art and explicitly replace selected uses; preserve exceptions and review known/uncertain references. | Boards and kept art remain; replacements occur only at selected supported scope. | F-04 |
| SC-06 Compose scene | [Board](wireframes.html#board) | Paint ground, place house and person, adjust layers and atmosphere before attaching behavior. | A visible composition is editable without making a quest; appearance alone is not collision proof. | F-02, F-03 |
| SC-07 Floors and routes | [Board](wireframes.html#board) | Edit floor/layer, stair link, collision and walk-behind overlays separately; run across stairs and return. | Arrival, traversability and draw order can each be inspected and tested; no inference from tile art. | F-02 |
| SC-08 Reusable kit | [Artwork](wireframes.html#artwork) | Create a sheet with no board, draw a roof across cells, name/select tiles and preview repeating joins. | Editable source and reusable set remain available for later boards and a pack. | F-04, F-05 |
| SC-09 Awkward sheet | [Artwork](wireframes.html#artwork) | Grabber displays guessed grid, margins, spacing and transparency; adjust numeric values and selected cells before import. | Preview matches chosen cells; cancel leaves source/destination untouched and allows retry. | F-04 |
| SC-10 Seam repair | [Artwork](wireframes.html#artwork), [Board](wireframes.html#board) | Open board tile with neighboring cells locked, review uses, choose shared or supported unique scope and paint pixels. | Repeat and board previews expose the join; unrelated uses stay unchanged only after a supported unique operation. | F-04 |
| SC-11 Animate region | [Artwork](wireframes.html#artwork), [Animation](wireframes.html#animation) | Select waterfall region, duplicate and edit frames, scrub/onion-skin and view whole region on board. | Timing and actual synchronization support are visible; unsupported coupled channels remain unavailable. | F-05, F-06 |
| SC-12 Stamps and terrain | [Artwork](wireframes.html#artwork), [Board](wireframes.html#board) | Select a house with per-cell shade, make a stamp, preview anchor; optionally assign terrain roles and paint. | Explain whether placements are constituent cells or a supported live link; stamp does not imply behavior. | F-05 |
| SC-13 Atmosphere | [Board](wireframes.html#board), [Appearance](wireframes.html#appearance) | Place image with top-left anchor/layer, paint shade or place light, compare source versus proposed bake; preview full-board or current-view export. | Export includes explicitly selected content and overlays; cancelled bake leaves editable sources untouched. | F-03 |
| SC-14 Person by look | [Animation](wireframes.html#animation), [Board](wireframes.html#board) | Import sheet, label directions, preview stances and numeric collision/talk geometry, assign to person and place. | Return to the placed instance and test its actual interaction; shared graphics and local placement remain distinct. | F-06 |
| SC-15 Progression | [Database](wireframes.html#database) | Review hero's imported stat bindings, edit growth chart/table, select unlock conditions and compare equipment; choose starting party owner. | Selected system's actual rule and party setup are tested; multi-member storage and unknown combination rules are not presumed. | F-07 |
| SC-16 Useful items | [Database](wireframes.html#database), [Board](wireframes.html#board) | Configure item use cards; place a pickup/chest referencing it; separately choose supported shop stock and test inventory/equipment. | Acquisition, full-health refusal, ineligible equipment, cancellation and removal are observed, not assumed; price is not stock. | F-08 |
| SC-17 State and world | [Events](wireframes.html#events), [Board](wireframes.html#board) | Build guard branches and admission state, attach to placement, run no-key/key/already-admitted fixtures then re-enter board. | Actual branch, movement and persistent state can be checked separately; activation condition does not suppress refusal. | F-11, guard |
| SC-18 Fight design | [Effects](wireframes.html#effects), [Database](wireframes.html#database) | Link Poison → Venom Bite → enemy → encounter; inspect tactics, rewards and selected system; run supported battle fixture. | Trace reports actual application/removal and rewards under that provider, without inventing duration/stacking rules. | F-09 |
| SC-19 Common action | [Events](wireframes.html#events) | Select a supported “give item” or “open door” structured action, choose named target and Show as code. | Creator understands action/ordering and can test it without a syntax lesson; unsupported actions stay code. | F-11 |
| SC-20 Learn code | [Events](wireframes.html#events) | Open example, inspect command help and fixture, change one statement, run and inspect resulting values. | Explanation is tied to observed state and exact source remains accessible; parser acceptance alone is not execution. | F-11 |
| SC-21 Code-first | [Events](wireframes.html#events), [Settings](wireframes.html#settings) | Open code and configuration directly, write a custom mechanic, run supported fixture and attach to board. | Code-to-test path never requires visual round-trip; unsupported plugin/runtime capability is visible. | F-11, F-12 |
| SC-22 Custom screen | [Appearance](wireframes.html#appearance) | Choose legacy skin or, only with a layout provider, arrange labeled text/image/button elements with representative data. | Skin changes window/button graphics; layout preview is distinct from real runtime input and battle logic. | F-12 |
| SC-23 Unusual mechanic | [Events](wireframes.html#events) | Make a small puzzle/minigame program, set minimal fixture and run it before building a whole game. | Supported behaviors and failures are visible; missing extension or runtime capability is named, not simulated. | F-11 |
| SC-24 Configure extension | [Settings](wireframes.html#settings), [Database](wireframes.html#database) | Inspect pack origin, version, capabilities, data ownership and order before explicitly enabling; configure offered fields and test. | Selected provider is explicit; unsupported contribution data survives and absence blocks only dependent work. | F-12 |
| SC-25 Author extension editor | [Settings](wireframes.html#settings), [Database](wireframes.html#database) | Propose schema fields or specialist panel, then exercise save/reopen/undo, validation and missing-provider fallback on each intended host. | A future contribution contract must preserve owned data and lifecycle; no editor API, trust model or host support is asserted. | F-12 |
| SC-26 Local test | [Board](wireframes.html#board), [Events](wireframes.html#events) | Select safe position adjacent to trigger; save and choose Play from here, or choose explicit program fixture. | Running revision and start state are shown; ordinary Play from game start is a separate action. | F-01, F-02, F-11 |
| SC-27 Diagnose | [Events](wireframes.html#events), [Board](wireframes.html#board) | Open failing trigger, inspect actual branch/watch values, breakpoint or collision overlay where supported. | Trace identifies observed divergence and navigates to owner; editor does not invent why the author intended it. | F-11 |
| SC-28 Compare combat | [Effects](wireframes.html#effects) | Record party, enemy, seed, version and selected provider; run two supported fixtures and compare actual events. | Measured differences are distinguished from a provider-specific prediction; ordinary Play is not labeled repeatable. | F-09 |
| SC-29 Recovery | [Workspace](wireframes.html#workspace) | After failed save or interruption, review available durable save, host backup and draft, including timestamps and differences. | Choose actual available version; missing draft/backup is explicit; retry or export is offered only when host supports it. | F-13 |
| SC-30 Shared revision | [Artwork](wireframes.html#artwork), [Database](wireframes.html#database) | Before rename/delete/shared effect or art edit, inspect known uses and uncertain dynamic references, choose apply/copy/replace/cancel. | Impact is honest and creator-controlled; project-wide atomicity or a complete use graph is not promised. | F-04, F-07, F-08 |
| SC-31 Editable handoff | [Delivery](wireframes.html#delivery) | Choose editable project output, inspect revision, dependencies, rights, excluded machine-local paths and destination. | Recipient opens the intended source revision in a clean environment; unchecked dependencies remain reported. | F-13 |
| SC-32 Playable handoff | [Delivery](wireframes.html#delivery) | Choose playable distribution, run preflight, inspect produced files, then test package in recipient context. | Recipient tests the actual output rather than development source; hosting is separate and conditional. | F-13 |
| SC-33 Occasional setting | [Settings](wireframes.html#settings) | Search movement, cursor, startup or key binding; inspect effective value/source, preview hotspot and resolve key conflict before apply/save. | Owner is discoverable and unrelated bindings remain intact; Cancel retains old setting. | F-01 |
| SC-34 Creator accessibility | [Workspace](wireframes.html#workspace), [Board](wireframes.html#board) | Use keyboard/tree/numeric alternatives to select a board object, edit geometry and visit an asset; scale panels or reduce motion. | Focus returns to origin, controls announce state/scope, and no operation depends solely on color, audio or pointer. This is a target, not an audit. | F-01, F-02, F-04 |
| SC-35 Conversation with authorship | [Events](wireframes.html#events) | If optional service is available, ask to recognize a badge but retain dialogue; review material shared and scoped proposed diff. | Reject unrelated edits; no code executes or files change without explicit approval; direct authoring remains available. | F-11 |
| SC-36 No assistant | [Workspace](wireframes.html#workspace), [Events](wireframes.html#events) | Decline conversation; draw, configure, use local help and code directly, including offline where host capabilities allow. | No account, generated edit or chat is required for ordinary local authoring; unavailable host/runner functions are disclosed. | F-01, F-11, F-13 |
| SC-37 Switch representations | [Events](wireframes.html#events) | Open structured sequence, Show as code, add handwritten exception, then return to visual view only where supported. | Exact unsupported source survives; ownership and conversion boundaries are visible, never regenerated over silently. | F-11 |
| SC-38 Connect places | [Board](wireframes.html#board) | Select doorway, choose destination and arrival, inspect return link, entry program and separate threads; test both directions. | Creator can identify a trapped destination and repair/return safely; dynamic destinations are not claimed fully mapped. | F-02 |
| SC-39 Interruptible scene | [Events](wireframes.html#events), [Board](wireframes.html#board) | Stage movement, dialogue, audio and waits; author explicit full and skip paths; run each from same fixture. | Inspect final position, state and restored controls in both actual runs; concurrency/wait semantics come from current supported system. | F-11 |
| SC-40 Sound in context | [Animation](wireframes.html#animation), [Appearance](wireframes.html#appearance) | Audition board music, battle sound roles and animation frame marker; inspect project audio setup, save and test transitions. | Frame association follows frame identity; actual host playback and loop handoff are checked separately from audition. | F-06, F-10 |
| SC-41 Noncombat | [Workspace](wireframes.html#workspace), [Events](wireframes.html#events), [Database](wireframes.html#database) | Start with boards, people and dialogue/state; leave encounters and progression unconfigured where supported. | No enemies or levels are prerequisite to a walking story; disabling a combat system is not implied merely by hiding controls. | F-01, F-07, F-11 |
| SC-42 Bulk tune | [Database](wireframes.html#database) | Promote item comparison, select early-game potions, set proposed price/effect change; table shows old/new, units and excluded exceptions. | Only explicit rows/fields are applied after review; batch transaction and cross-document undo are conditional. | F-07, F-08, F-09 |
| SC-43 Reuse behavior | [Events](wireframes.html#events), [Board](wireframes.html#board) | Duplicate chest behavior, decide shared program versus independent copy; set distinct key, reward and opened state for each placement. | Test both chests and re-entry; per-instance persistence only offered when the model supports it. | F-11 |
| SC-44 External edit | [Artwork](wireframes.html#artwork), [Events](wireframes.html#events) | External tool changes a locally dirty file; show local, external and baseline if available, then choose retain, reload or manual reconciliation. | Both versions survive until explicit resolution; absent external-editor capability is disclosed. | F-04 |
| SC-45 Overlapping contributions | [Delivery](wireframes.html#delivery), [Board](wireframes.html#board) | Import/review two revisions against their common baseline; inspect conflicting tiles, objects and references, choose resolutions manually. | Preserve both originals and identify semantic conflicts even when text merges; no live collaboration or automatic semantic merge assumed. | F-13 |
| SC-46 Translation | [Appearance](wireframes.html#appearance), [Events](wireframes.html#events) | Review text with speaker and branch context, translate without changing conditions, preview longer substitutions and missing glyphs. | Branches remain unchanged and clipping is inspected in real supported output; localization storage and handoff model remain open. | F-12, F-11 |
| SC-47 Bounded exercise | [Events](wireframes.html#events), [Workspace](wireframes.html#workspace) | Open a copy of a prepared example, change one action, inspect fixture result and explain it; reset the exercise copy only. | Learner can experiment in code or actions without overwriting the source; reset depends on actual copy/recovery support. | F-11, F-13 |
| SC-48 Short session elsewhere | [Workspace](wireframes.html#workspace), [Delivery](wireframes.html#delivery) | Compare machine's local project revision and last durable save with explicitly transferred copy, then reopen last task if available. | Creator knows which revision is open and can make/save a small change; no cloud synchronization or cross-device draft assumed. | F-13 |
| SC-49 Legacy preservation | [Delivery](wireframes.html#delivery) | Import Toolkit root or explicit main/assets into a copy; inspect inventory and unsupported plugin/missing-main report before conversion. | Original survives; unresolved dependencies remain visible and conversion can be cancelled. | F-13 |
| SC-50 Editable ingredients | [Artwork](wireframes.html#artwork), [Delivery](wireframes.html#delivery) | Select house stamp/sheet sources, dependencies and attribution; review rights and export asset pack; import into another project. | Recipient can inspect/edit supported ingredients, distinct from full project and player game; permission is not inferred. | F-05, F-13 |
| SC-51 Released game | [Delivery](wireframes.html#delivery), [Events](wireframes.html#events) | Record reported build and starting state, reproduce using supported fixture, fix, package a uniquely identified build and retest. | Report ties fix to tested output; player-save compatibility is explicitly unknown unless separately verified. | F-13, F-11 |
| SC-52 Accessible gameplay | [Settings](wireframes.html#settings), [Appearance](wireframes.html#appearance), [Events](wireframes.html#events) | Configure alternative inputs and non-color/non-audio cues where supported, then play with those alternatives and inspect timing/branches. | Tests assess game output, not merely editor keyboard access; unsupported player accommodations are named. | F-01, F-12, F-11 |
| SC-53 Organize at scale | [Workspace](wireframes.html#workspace), [Delivery](wireframes.html#delivery) | Search similarly named assets, follow known references to the effective one, preview rename/delete and uncertain script references. | Choose preservation, replacement or manual review; “unused” is not treated as proven when dynamic references may exist. | F-13 |
| SC-54 Extension conflict | [Settings](wireframes.html#settings), [Effects](wireframes.html#effects) | Compare prior/current provider versions and order, selectively disable or reorder, retain plugin data and rerun known test. | Identify observed working combination where available; no silent fallback, destructive migration or promised rollback. | F-12 |

## Flow index

F-01 settings/start; F-02 connected boards; F-03 atmosphere/export; F-04 tile revision/import/conflict; F-05 stamps/region animation; F-06 looks/animation; F-07 progression/party; F-08 items/acquisition; F-09 enemy/effect/battle; F-10 audio; F-11 events/code/fixtures; F-12 appearance/plugins; F-13 preservation/organization/delivery. The table extends those rehearsals for the special cases rather than claiming the original flow already solved them.
