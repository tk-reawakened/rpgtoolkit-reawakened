# Runtime audio playback evidence — 32.1 / #3470

This spike measures one probe implementation. It does not select a codec, approve a dependency, or change the [audio format policy](../../../../docs/spec/engine/audio-media.md#audio-format-policy). Export and import UX remain with [14.11 / #1752](https://github.com/tk-reawakened/rpgtoolkit-reawakened/issues/1752).

## Reproduction

Measured on macOS 27.2 (build 26B123), arm64, Node 26.13.0, pnpm 12.10.1, and Playwright 1.64.0. Android uses the project's installed Capacitor CLI 8.6.2 / Android platform 8.4.3, SDK, and JDK 21.0.13.0.3. Run from an isolated checkout with the local dependencies installed. The Gradle project, web assets, APK, package and logs are generated there, not committed.

```sh
pnpm build
pnpm fixtures:fetch
pnpm make-package fixtures/legacy/demo --closing-plan golden/closing/plan.json --game demo --out fixtures/packages/demo.tpk
pnpm desktop:build
node tools/spikes/runtime-audio/fixtures.mjs

# Set the installed JDK/SDK paths for the Capacitor lane (macOS example).
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$JAVA_HOME/bin:$PATH"

for host in browser electron capacitor; do
  for rate in 44100 48000; do
    node tools/spikes/runtime-audio/run.mjs --host "$host" --rate "$rate"
    sleep 3
  done
done
```

On a cloned worktree with copied build output, refresh the exact workspace audio code before running: `pnpm exec tsc -b --force packages/core packages/synth packages/runner-web`, then rerun `pnpm desktop:build`. An initial attempt inherited stale `dist` exports (tracked in [#3107](https://github.com/tk-reawakened/rpgtoolkit-reawakened/issues/3107)); rebuilt page and worklet hashes changed. The final matrix uses the rebuilt inputs, not the earlier runs. The package regenerated byte-for-byte.

Each invocation runs the short and long tracks serially, or one with `--fixture short|long`. The browser lane uses the project's Playwright Chromium (`pnpm exec playwright install chromium` if missing); Electron uses the built app. Android generates a separate Capacitor project and debug APK below the run directory. It boots an existing AVD definition with private writable images, a 4 GiB data partition and no snapshots. A per-run ADB daemon listens only on a private Unix socket in a non-writable directory; USB and mDNS are disabled, and the local emulator scan is capped at the selected console port. Dedicated loopback-only relays connect the emulator and Playwright to that same daemon without exposing the socket. Before any ADB access, the probe verifies `lsof` reports both selected console/ADB ports as listeners owned by the launched emulator process tree, then checks the sole online `emulator-<consolePort>` transport and exact `adb emu avd name`; the process-tree/port and transport checks repeat before every device write. On daemon loss, relay connections fail and the socket directory prevents implicit ADB restart. No shared daemon or external serial is used. `--adb` and `--avd` select installed tooling and an AVD definition. Save `artifacts/runtime-audio/fixtures/manifest.json` and `artifacts/runtime-audio/hosts/`; use the report IDs below to distinguish proof results from setup attempts.

Exact encoding recipe:

```sh
ffmpeg -hide_banner -y -i source.wav -c:a libopus -b:a 96k -vbr off -compression_level 10 \
  -frame_duration 20 -application audio -map_metadata -1 -fflags +bitexact output.ogg
```

The generator's [RFC 7845](https://www.rfc-editor.org/rfc/rfc7845.html) / [RFC 6716](https://www.rfc-editor.org/rfc/rfc6716.html) inspector checks CRC/lacing, header placement, single-stream identity, packet framing and TOC durations, page granules and final packet clipping without calling an encoder or decoder. The separate [WAV length oracle](../../../../tools/fixtures/audio/length.mjs) checks FFmpeg-decoded frames; FFmpeg encoding and decoding are not independent of each other. Both FFmpeg-decoded peak impulses are at the exact authored frame 24,000; a 5 ms tolerance in the assertion would reject a whole 312-frame/6.5 ms pre-skip shift.

## Packaged host playback

Each row reads the same canonical package. Chromium gets it from loopback HTTP; built Electron goes through `desktop.openPackage()` (preload IPC) at `app://player`; the installed Capacitor APK loads it from `https://localhost`. The disposable page uses the corresponding shipped CSP. A script inserted as the negative control really was blocked; the external page script and worklet did run. Browser and Android have no WebAssembly allowance; desktop preserves the existing narrow `'wasm-unsafe-eval'` allowance for its separate SF3 path. No autoplay bypass is passed. The report records the context's state before the gesture, at the trusted click/touch, and after `resume()`. A context already running on a host is not evidence of an unlock transition.

`AudioContext.decodeAudioData` decodes the exact Opus entry at the graph rate; the probe requires the native channel count to match the authored stereo layout before conversion. That does not establish channel separation: this fixture deliberately uses the same source signal on both channels. The disposable adapter converts the result to PCM16 WAV, transfers it to an AudioWorklet, and registers it only in the probe behind the production `AudioSource` seam. Both formats run the same cue timeline and capture routine through the production `PcmSink`. In the matched WAV run the exact WAV entry goes directly to the production PCM source, without the native decoder or conversion. Both runs also play the existing MIDI fixture through the production Spessa source with the project's plain TK-16 SF2 bank; that is not compressed SF3 evidence.

Hosts: Playwright headless Chromium 156.0.8078.4; Electron 45.2.1 / Chromium 156.0.8078.75; and Android 13 / API 33 WebView 101.0.4951.74 in a Capacitor debug APK on the arm64 Pixel 3a AVD (`sdk_gphone64_arm64`, emulator 31.3.10.0). The host runs used tooling commit `ef523d943584e1319d8cc6079eeebb55c71ea38c` with workspace artifacts rebuilt from its pinned source.

`Frames` is native Opus output / the exact oracle-derived target at the observed graph rate. `Loop error` is the measured interval between authored impulse landmarks minus the exact interval. The short leg renders an entire iteration and its repeat before overlap. The 60-second leg plays both voices, stops the second and seeks the first to its last 30 ticks, then captures the real wrap; it does not run for 60 seconds or test long-term drift. `Startup` measures gesture → first analyser energy. It includes TPK extraction and the probe/host path, and includes about 250 ms of authored silence. It is not time to audible sound on a speaker.

### Memory, copy and transfer

`Baseline / overlap / peak / after` are samples before each gesture, during the **page-observed** two-voice window, the highest sampled value, and after context close. Sampling starts after the page receives the worklet's effect-render acknowledgement and the page must still report the window open when sampling finishes. Worklet messages can be delayed, so this is not a sample synchronized to the exact last rendered frame. The legs run WAV then Opus in fresh documents on the same host. Caches and reclamation are uncontrolled: working-set differences do not isolate decoder allocations and `after` is not retained heap after GC. Chromium and Electron process-tree RSS can double-count shared pages. Android `dumpsys meminfo` covers the app process, not separate WebView renderers or the whole emulator. `performance.memory` can be coarse and excludes native PCM.

## Negative lanes and falsification

Each Opus run requires exactly four negative load/play pairs and zero captured PCM: a missing media-index key, truncated Ogg, an unrecognized format, and the valid fixture after discarding the probe's prepared native sample. The host controller checks these four independent IDs and their ordered source and invalid-play diagnostics. Native Web Audio also rejects the truncated stream. The discarded-sample case does not show that a host lacks a native decoder. Unsupported mapping/layout and chaining are separate packet-oracle negatives, not claims about other layouts in native decoders.

The same positive assertions were run against deliberately changed test inputs, then restored. The waveform tests retain their cue markers or correlation input but remove the rendered repeat or mute one voice. The lookup test substitutes an absent key in the real package. The negative-lane test drops a required diagnostic row, and the real core test deliberately omits its rewind. All five commands exit 1 at the named assertion, not an unrelated read or setup error; the unperturbed test module passes.

## Limits and handoff

- The worklet uses real production source, mixer and cue code, but a different probe processor and temporary source registration. Unmodified players still have only their ruled audio sources, and the current core does not derive compressed duration metadata. No format is selected here.
- [`decodeAudioData`](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/decodeAudioData) decodes a complete file and resamples to the context rate. It made the ownership and copy costs visible, but it does not make per-asset streaming or host-agnostic deterministic timing automatic. A future experiment with [WebCodecs' Opus registration](https://www.w3.org/TR/webcodecs-opus-codec-registration/) must supply and independently validate demuxed packets, timestamps and trim metadata; pass/fail from API support checks would not substitute for another packaged-host proof. `HTMLMediaElement` by itself would not test the existing tick-addressable voice controls or mixing contract.
- During setup, an APK install hit the original AVD image's capacity. For the final rows, the installed SDK boots a disposable 4 GiB image and installs an isolated APK. WebView 101 lacks the `Element.checkVisibility` API used by the current Playwright locator; on Android, the harness reads the enabled button's DOM rectangle and sends one bounded trusted CDP touch without altering the page or the policy.
- Physical phone/speaker output, iOS (only macOS Command Line Tools were installed; `xcrun simctl` was unavailable), other browser engines, Windows/Linux Electron and long-duration drift remain **unproven**. Do not infer them from this Mac or from an emulator.

**Handoff to [14.11 / #1752](https://github.com/tk-reawakened/rpgtoolkit-reawakened/issues/1752):** Keep the WAV/MIDI player rules while deciding authoring tools and profile policy. The portability result is for native decode plus a probe-only PCM adapter on the observed builds. Treat long-clip costs, the 44.1 kHz frame difference, and explicit failures as requirements for future evaluation, not a design decision. Check channel separation and speaker output if they matter to the eventual profile, and compare warm/cold and repeated-overlap memory before setting an allocation budget.

## Author-installed tools, not player support

The recipe comparison used the same authored 2-second, 48 kHz stereo WAV input. Every FFmpeg row below was run with `ffmpeg -v error -y -i source.wav` followed by the listed arguments; codec, rate and channels were checked with `ffprobe -v error -select_streams a:0 -show_entries stream=codec_name,sample_rate,channels:format=size -of csv=p=0 OUTPUT`. Every output reported 48,000 Hz and two channels. The byte sizes describe this mostly single-tone file, not typical game music or a quality comparison.

The fixture generator explicitly refuses a missing `ffmpeg` or absent `libopus`, and surfaces stderr if encode or decode fails. ### Copyright, patents and redistribution

- **Fixture rights:** the stereo signal is authored by the spike (440 Hz tone, a half-second impulse and quarter-second lead/tail silence). The input WAV, generated Opus file, fetched demo assets and generated package are not checked in. Author-installed programs create data; no encoder binary or program code is copied into the game or project artefacts.
- **Reference implementation:** local Homebrew `opus` 1.6.1 supplied `libopus.0.dylib`. [Xiph's Opus licence page](https://opus-codec.org/license/) identifies BSD-3-Clause for the reference implementation. Any future redistribution would require the exact release, full copyright and notice/disclaimer, and applicable transitive component review under [G6](../../../../docs/guardrails.md#g6--licence-gate). The same page identifies `opusenc`/`opusdec` as BSD-3-Clause and separately identifies `opusinfo` as GPLv2; review the actual tool/component set, including libogg and libopusenc if selected, rather than treating `opus-tools` as one licence.
- **Patent scope:** upstream lists conditional royalty-free grants from Xiph, Broadcom and Microsoft; the terms differ, including termination and Microsoft's reciprocity terms. Those grants are not a determination that every third-party claim or jurisdiction is cleared. The spike made no legal judgement on Opus, AAC, MP3 or any other codec, and did not select any player dependency.
- **External authoring binary:** FFmpeg 9.0.1 from Homebrew formula `ffmpeg 9.0.1_1` was built with `--enable-gpl`, `--enable-version3`, `--enable-libopus`, `--enable-libmp3lame`, `--enable-libx264` and `--enable-libx265` among other switches. `ffmpeg -buildconf` is captured in the fixture manifest. FFmpeg's [upstream legal page](https://ffmpeg.org/legal.html) explains the LGPL baseline and effect of GPL options; this build is not eligible to ship under project G6. [Audacity's 3.7.5 licence](https://raw.githubusercontent.com/audacity/audacity/Audacity-3.7.5/LICENSE.txt) is GPLv3; that author tool and its optional FFmpeg integration are not candidates for inclusion here.
- **Host-provided decoder:** the spike calls `AudioContext.decodeAudioData` already present in the tested hosts. It does not add a decoder, enable a disabled desktop/mobile codec flag, or establish the licence, notice or patent status of any other Electron or WebView build. A future bundling decision must inspect the actual distributed binary and notices rather than generalizing from a web API or a permissively licensed reference implementation.
