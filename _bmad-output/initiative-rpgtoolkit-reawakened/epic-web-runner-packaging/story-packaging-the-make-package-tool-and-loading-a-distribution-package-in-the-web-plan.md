# Packaging: the make-package tool and loading a distribution package in the web runner

## Intent

Let an author turn a folder into the one file a game *is*, with the descriptor a library registers it from, and let the
web runner boot that file with no folder access — proved by the same committed hashes the folder boot reaches.

## Scope

`tools/make-package` (the CLI and its tests), `packages/runner-web` (`packageFiles`, the page's package mode) and the
browser lane. The editor's T-70 button stays `epic-editor-assets-p0`'s and will call the same writer.

## Decisions taken here

1. **One tool, two artefacts, no executable.** `pnpm make-package <folder>` writes `<out>.tpk` and its sibling
   `<out>.tpk.json`. Nothing wraps, launches or associates: installing is registering. The descriptor holds exactly
   `schema`, `file`, `sha256`, `size`, `gameId`, `title`, `version`, and `gameId` is core's own derivation
   (`deriveGameId(mainBytes, title)`), so a library and a save area agree on identity.
2. **The package keeps the spec's manifest and nothing more.** `manifest.json` holds exactly `schema`, `main` and
   `index`; the index lists **every** game file including the main, in code-unit order, and excludes only the manifest.
   The descriptor is a sibling, never a manifest field — which is why two exports of one tree stay byte-identical.
3. **The folder is untrusted input.** The tool reads it through `loadPackage({ kind: "folder" })`, so the loose-folder
   limits L22–L26 apply before anything is packaged, and the writer then applies L1–L21, so the tool cannot emit a
   package the reader would refuse. A refusal names the rule it hit.
4. **A synthesised main is materialised, not faked.** `demo` and `Basic` ship no `Main/<game>.gam`; their main comes from
   the closing plan's `synthesised` block. `--closing-plan <plan> --game <name>` writes that main at the path a package
   keeps it at, using the same construction the closing suite performs, so the packaged demo is the demo the baselines
   were recorded from.
5. **The runner serves a package through the same file map as a folder.** `packageFiles` runs the package through
   `loadPackage`, drops `manifest.json` (package bookkeeping, never a game asset) and returns `ClosingFiles`, so the boot
   path, the hashing and the frame are identical; only the door differs.
6. **`--check-descriptor` is the host's refusal.** It validates the file name, SHA-256, size and the exact field set, and
   prints each problem, so a tampered package is refused with a reason rather than a boolean.

## Verification

- `tools/make-package/test/make-package.test.mjs` (9): a written package reloads to identical bytes and a three-field
  manifest; the descriptor names the file, SHA-256 and size; a tampered package and a wrong file name fail the check; two
  exports are byte-identical; only the two artefacts are written and the bytes are not an executable; an escaping path is
  refused by L9; a missing or doubled main is refused; the index order is the writer's.
- `tools/browser/tests/package.spec.ts`: `demo` boots from `fixtures/packages/demo.tpk` alone — `/api/game` intercepted
  and never requested — to tick 120, state `bff947dce3a11b4f`, draw `9a40be8a0b5ca816`, 128 commands, 0 deferred.
- The package fixture is generated by the lane's own server command from the fetched sample game, so nothing binary is
  committed and `fixtures/packages/` is ignored.
