# Monaco CSP spike evidence

Research for [#2183](https://github.com/tk-reawakened/rpgtoolkit-reawakened/issues/2183); recommendation in [proposed ADR 0029](../../adr/0029-monaco-csp-style-src.md). Base `0872e406`, 2026-11-12, macOS arm64, Node 26.13.0, Playwright 1.64.0 / Chromium 156. Reproduce with the commands in [dock findings](../dock-library/README.md); dependencies and outputs stay outside the workspace. All policy strings, measured results, and bundle scans are in [raw/](raw/). The actual VS Code webview run used VS Code web 1.146.0, build `69047191fc427f2f92828279aae1d90d8eeda7ab`; Electron was 45.2.1 / Chromium 156 over `app://` in a scratch window, not a packaged editor.

The Monaco 0.57.0 sample uses a custom toy grammar, not the project's LSP, creates the editor, types and undoes, opens completion and find, and verifies worker messages, line positions, token colour, current-line width and codicon loading. CSP counts vary with rendering. The web-host policy exactly is `default-src 'none'; base-uri 'none'; connect-src 'self'; img-src 'self' data:; script-src 'self'; style-src 'self'; frame-ancestors 'none'` (the last directive is ignored in meta; [#2184](https://github.com/tk-reawakened/rpgtoolkit-reawakened/issues/2184)).

| Browser configuration | Results after use |
|---|---|
| Web policy unchanged | Font blocked, 6 `style-src-elem`, over 120 `style-src-attr` violations; typing/undo worked but token colour, current-line width and icon font did not. Same-origin classic editor worker exchanged 17 messages. |
| Add `font-src 'self'` and `style-src-attr 'unsafe-inline'` | Six element-style violations remained; token colour absent. |
| Add `font-src 'self'`, `style-src-attr 'unsafe-inline'`, `style-src-elem 'self' 'unsafe-inline'` | Zero violations; colour, find icons, typing, undo and worker-backed suggestion worked. `style-src 'self' 'unsafe-inline'` plus font source also produced zero. |
| Add `font-src 'self'`, `style-src-attr 'unsafe-inline'`, `style-src-elem 'self' 'nonce-N'`, plus an **esbuild source patch** that adds N to Monaco's style elements | Zero violations and same sample checks passed; upstream Monaco 0.57 has no style nonce API found. A static page needs a fresh unpredictable nonce delivered consistently in its CSP and script; a fixed checked-in nonce is not a security nonce. |
| Monaco default blob-worker path with relaxed styles but no blob worker allowance | `worker-src` violation; worker errors and no suggestion rows. Adding `worker-src 'self' blob:` restored worker messages and zero violations. A same-origin classic worker via `getWorker` did not need blob on HTTP or app:// in this test. |

The real VS Code webview uses native text editors per ADR 0021; embedding Monaco there is a hypothetical probe, not the implementation plan. Its verbatim CSP blocked inline styles and the font, and a direct resource-origin worker threw a cross-origin error; Monaco warned that it fell back to the main thread. With a build-time nonce patch, `style-src-attr 'unsafe-inline'`, `font-src ${webview.cspSource}`, `connect-src ${webview.cspSource}` and `worker-src blob:`, fetching the worker and creating a blob worker yielded zero observed violations and 17 messages. The resource-origin worker remained inaccessible even with CSP permission. The listener may miss violations before bundle execution; console captured the initial font block. See `raw/verbatim.json` and the two `raw/proposed+*.json` for actual origin-expanded policies and warnings. This webview experiment is not a reason to relax the existing visual-editor CSP.

The minified Monaco core-contributions bundle (all `editor.main` editor contributions, no bundled language registrations, plus toy grammar) was 3,951,523 B JS for the fetch-blob/nonce variant; classic variant and compressed sizes are in `raw/build.json`. The classic build emitted roughly 3.95 MB JS, 175,654 B CSS, a 153,228 B codicon font and 307,264 B classic worker. Full bundled-language JS was about 4.55 MB. These are spike bundles, not a shipped build. CodeMirror 6 basicSetup was ~396 KB minified JS plus 293 B CSS; its features are not equivalent to Monaco. In light DOM its runtime `<style>` violated strict web CSP and tokens lost colour; VS Code's style nonce worked. A shadow-root mount used one adopted stylesheet and zero observed violations under web strict CSP, with colour, typing, undo and find working in this Chromium test. CodeMirror is an alternative only if ADR 0021 is amended, not a fresh choice made here.

## G6 inventory and limits

`raw/package-inventory.json` records installed package names, exact versions, SPDX fields and dependency declarations; it is not a legal clearance of every file. Monaco is MIT; declared `marked` 14.0.0 is MIT, `dompurify` 3.4.15 is `(MPL-2.0 OR Apache-2.0)` and the Apache option must be chosen. The bundle includes Monaco's vendored copies (DOMPurify's retained header identifies both choices; marked source states MIT). `ThirdPartyNotices.txt` also lists Node path (MIT), TypeScript and associated specification/data material including CC-BY and W3C terms; the all-language distribution is **not** automatically cleared merely by the package's MIT field. The codicon font is bundled; its provenance and licence must be verified against its source before shipping and it needs an asset notice. The upstream [codicons repository](https://github.com/microsoft/vscode-codicons) uses CC-BY-4.0 for icons, which is not on the pinned Blue Oak list. No G6 exception or permission is asserted. Audit exactly the shipped inputs, all notices and the font, then run the actual licence and production audit gates when integrating. CodeMirror's installed packages declare MIT, but the same shipped-input audit applies.

Not tested: real RPGCode language-service integration, model lifecycle, cross-browser compatibility, screen readers, offline packaging, actual packaged Electron editor, or a full hash strategy across dynamic theme/decoration CSS. Nonce/hash of element styles does not permit arbitrary style attributes; `'unsafe-hashes'` requires hashes for every permitted attribute value and is not evaluated as a scalable solution. A nonce patch is experimental, fragile across Monaco upgrades, and not an upstream-supported API.
