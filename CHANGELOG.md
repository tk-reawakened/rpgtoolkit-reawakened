# Changelog

## Unreleased
- The mobile wrapper exists up to its device proof: `runner-mobile` with `capacitor.config.json` (Capacitor 8.5.3, `webDir dist`), a host service implementing the same four calls as the desktop preload over an injectable filesystem (AD-17 keys under `saves/<gameId>/…`, an escaping path refused, a base64 read decoded), and the player page **extracted into `runner-web`** so the desktop shell and the mobile wrapper run one implementation rather than two renderers. A browser spec boots the mobile page against a Capacitor-shaped filesystem stub and reaches tick 120, state `bff947dce3a11b4f`, draw `9a40be8a0b5ca816`. **No claim is made that a device or emulator ran**: that step is the owner's, and the plan carries the commands and the pass condition.
- `runner-desktop` exists: the **player's** Electron 45.2.1 shell around the `runner-web` build, with its pages served over a privileged `app://` scheme registered as `standard`, `secure`, `supportFetchAPI` and `corsEnabled` before `app.ready` (never `loadFile`), no service worker registered, a package read from disk through `packageFiles`, and a save-blob host behind AD-17's keys (`userData/saves/<gameId>/…`) behind a four-call `contextBridge`. It carries no editor code and no window chrome. Measured on macOS arm64: a package from disk boots `demo` over `app://` to tick 120, state `bff947dce3a11b4f`, draw `9a40be8a0b5ca816`, WebGL2 present (max texture 16,384), the D-7 blend exact, 15 ticks of non-silent audio, and the same draw list rendering the same frame as the reference rasteriser (worst channel 0).
- The desktop licence inventory check (`tools/licences/desktop-inventory.mjs`) reads `LICENSES.chromium.html` and `libffmpeg.*` from the built Electron distribution under `guardrail-exception: G6 ADR-0013`, and says "not built yet" rather than passing silently when there is no artefact. A `desktop` CI job runs the measurement on Linux (under Xvfb), macOS and Windows; **the Linux and Windows numbers are that job's to produce and were not measured in the entry's first landing.**
- The core now computes a deterministic prefetch plan and sends it as tiered hints (`{ kind: "prefetch", reqId, hints }`) at the AD-5 seam: `now` carries the current board's music (and the default bank when it is a MIDI), `next` the music of boards reachable by edge links and the battle background's five sound fields, `always` the main file's three menu sounds and the default bank. A key appears once, in the earliest tier it belongs to, ordered by tier then key, and a plan is sent only when it differs from the last one — on boot's scene board, an ordinary `send`, a recovery resume and a return from battle.
- A hint is provably hash-neutral: it earns no reply, no state or draw hash reads it, and its `reqId` comes from a separate counter rather than the saved `nextRequestId` (drawing from that one moved every sample game's state hash). The engine's `HOST_REQUEST_KINDS` and the harness's `isRequest` guard both know the kind, so a hint is observed rather than dropped, and a test runs one board against a host that observes hints and one that discards them and compares both hashes.
- Two shares of the audio table are **not** in the plan yet and are documented as such: the `.anm` frame sounds of the animations a board uses (needs a board-actor walk the hydrated board does not carry) and literal `send("<board>")` targets (needs a program-source scan). A linked board's music is hinted only when its bytes are already cached, because a hint never causes a read.
- A game folder can become the project's single-file package and its install descriptor with `pnpm make-package <folder> [--out <file.tpk>] [--title <name>] [--version <string>]`. The package is a `.tpk`-compatible ZIP whose root is the folder, with `manifest.json` at the archive root holding exactly `schema`, `main` and `index` (the main included, in code-unit order), and nothing else; the tool emits **no executable**. Beside it goes `<file>.tpk.json` with exactly `schema`, `file`, `sha256`, `size`, `gameId`, `title` and `version`, so a library registers a game without parsing the archive. `--check-descriptor <file>` validates a descriptor against the file it names — a tampered package is refused with the reason — and `--verify <file>` reloads a package and prints its manifest facts.
- The folder is untrusted like any package: the tool reads it through `loadPackage({ kind: "folder" })`, so the loose-folder limits L22–L26 and the writer's L1–L21 both apply and a refusal names the rule it hit. Two exports of one asset tree are byte-identical.
- A closing-plan entry that synthesises its main file (the `demo` and `Basic` samples ship no `Main/<game>.gam`) can be packaged with `--closing-plan golden/closing/plan.json --game demo`: the main is materialised at `Main/<game>.gam` from the same construction the closing suite uses.
- The web runner boots a game from one package, with no folder access: `packageFiles` runs the package through the untrusted-input limits and returns the same file map the folder path produces, so `demo` reaches its committed tick-120 hashes (`bff947dce3a11b4f` state, `9a40be8a0b5ca816` draw) from `?package=fixtures/packages/demo.tpk` while the folder endpoint is never requested.
- The SoundFont path is live. The effective bank resolves through the four ranks the spec names — player, author, runner, bundled, and no fifth (MEDIA-5 retired it) — and a bank is validated as a RIFF `sfbk` container against the runner's 8 MiB ceiling: a wrong container is `bank.invalid` and keeps the previous bank, an oversized one is `bank.unavailable`. The cache keys a bank by the SHA-256 of its bytes, so two games naming the same bytes share one entry and one load, and it never evicts a bank a voice is holding.
- `media/soundfonts/TK-16.sf2` loads and MIDI renders through it, in Node and in headless Chromium: the file hashes to the SHA-256 the notice records (`5419f02b…`), and a 120-tick MIDI fixture produces sound instead of silence. Its licence is CC0-1.0 and its provenance is recorded under `tools/licences/tk16-provenance.json`; choosing it as the *default* remains the owner's listening approval (PB-10), so a host that wants it off passes no bundled layer.
- The runner's video half lands: every `playVideo` is answered with exactly one `video.ended { reqId }` — including a missing asset (`media.video-missing`), an undecodable container (`media.video-format`) and a second request while one plays (`media.video-busy`) — one video is outstanding at a time, and the other realised voices are held through the cue player while the core's own restart cue returns the music. Presentation is CSS: full fits with the aspect kept, small is the video's own size, scaled down and never up.
- No VP9/WebM fixture ships yet, so the lane proves the missing, undecodable and busy paths; the played path needs a fixture and is entry 9.7's.
- The browser runner now has its audio half. `synth` carries the cue player: the start arithmetic is a pure function of the cue and the tick a voice became **ready** (`cueStart`), so lateness is measured from ready rather than from receipt, and it reproduces every committed cue-player expectation in the audio kit. `CuePlayer` is the state machine around it — the `(track, voice)` map, the prepared voice from `media.load`, the pre-ready message queue, the autoplay lock's mirror and the focus hold.
- `runner-web` carries the output: `PcmSink` holds one `synth` source voice per protocol voice and pulls frames, the same call a browser `AudioContext` graph makes, applying voice, bus and master volumes. A finite voice reports `ended` once and a looping one keeps sounding.
- Three runner rules are each a named test, in Node and in Chromium: the autoplay unlock is a delayed late start (a 30-tick loop cued at tick 0 joins at 15 when the gesture arrives at 45), the 15-tick drop is measured at ready (lateness 14 starts at 14; 15 is stopped and never played), and the focus hold pauses and resumes with its position intact.
- The audio vectors now commit the **whole** cue and the `loop`/`playing` facts a `media.seek` reads. Before, a runner expectation recorded only the cue's identity, so it could not pin the arithmetic it demonstrated; the generator gained those fields and the fixtures were regenerated.
- MIDI still needs a SoundFont bank: `setBank` is recorded and a voice whose source needs a bank fails with `bank.missing` instead of playing silence. The SoundFont path, the bank picker and the shared bank cache are entry 9.6's.
- `render-webgl2` now replays every AD-3 draw command in the browser, not just fills and blits: text (both the legacy bitmap font and TrueType outlines), the one-pixel Bresenham line, the integer-midpoint ellipse, the `.iso` projection, and the `pushTarget`/`popTarget` scratch stack. The pixel sets a GPU cannot derive on its own come from `core/raster`'s leaves (`linePixels`, `rectOutlinePixels`, `ellipsePixels`, `isoSourceOffset`, `textInk`), so the reference rasteriser and the replayer share one decision instead of two implementations. A text run whose family the game does not ship now draws in `DEFAULT_FONT_ASSET`, the same substitution the engine makes before it rasterises.
- A tiled blit uploads only the tile it names. A `.tst` strip of a large board can be wider than `MAX_TEXTURE_SIZE`, and an incomplete texture samples as black — which is why a 589-tile board used to present as a wrong frame with no diagnostic.
- The conformance kit grows from three vectors to sixteen (line, rectangle outline, ellipse outline and filled, `.iso` projection, legacy text, TrueType text, the R-15 tint remaps and the alpha-0 skip), and a new browser lane replays **every gating row of `golden/ledger.json`** through WebGL2, comparing each with its oracle and with itself after a full cache flush. All nineteen rows agree exactly today.
- A board shade layer that covers fewer cells than the grid is now refused instead of written, because the reader consumes a layer's records until the grid is covered and a short layer was read into the following fields.
- `font("Arial")`, `serif` and `monospace` now resolve to a font the project actually ships: the command resolves the name against the asset index (exact path, then family, then the documented Liberation substitution) instead of storing a path no project ships, which had silently fallen back to the bitmap font. Because the saved `ui.font.asset` is part of the hashed state, the Basic sample's recorded hashes move (its title and board frames do not); the closing checkpoints, the script golden and the corpus expectation were re-recorded with that reason (G5).
- Pending script audio starts retain their voice objects until that audio effect applies, so a handed-over handle is still the voice the play built and a board-music cancellation keeps a valid binding.
- A plugin id that is an inherited `Object.prototype` member (`constructor`, `__proto__`, `toString`) is now an unknown plugin with the located `plugin.unresolved` diagnostic, in boot and in the runner harness, instead of crashing boot when an inherited member is mistaken for a definition.
- Actor and battle writers now refuse a model their own readers would reject instead of writing bytes that mean something else: a vector-base or point list over the 32768-entry `i16` bound, an `i16`/`i32`/`i8` field outside its stored width, a character or item model that omits a stored `idleTime`/`speed`, and a wrong magic, an unlisted minor or a negative major version. The refusal is a located writer error naming the field and its range.
- Clarified that interruption recovery restores a validated pre-battle or settled ledger, not an active battle, while ordinary mid-battle saves retain their separate continuation contract.
- Saves now separate data shape from instruction positions. `schema.compiler` is replaced by `schema.ir` (mirrored on every program reference), `schema` moves to version 2 and `vm` to version 6, and every older save fixture migrates. A save whose instruction version is older still loads: its data sections migrate and each affected thread restarts from its saved source instead of the whole save being refused. A save from a newer instruction version is refused whole with `restore.ir-mismatch` and leaves the live game and its counters unchanged. Recovery candidates keep the stricter rule and refuse any instruction-version difference. `restore.compiler-mismatch` is retired, the game-ledger version moves to 2, and a committed lowering fingerprint now fails CI when the instruction stream changes without an `IR_VERSION` decision.
- Program `Put` edits now expire only with their owner: finished threads are cleaned up at end-of-thread-phase, while `killThread`, event-thread teardown, and board/item lifecycle removals expire edits synchronously before the numeric thread id can be reused. Overlapping edits keep the latest still-live program or board edit visible and restore the original board tile when none remain; `LayerPut` keeps its board lifetime.
- The engine now exposes one-shot interruption-recovery candidates requested by RPGCode `checkpoint()` at eligible settled points, plus a conservative pre-battle candidate captured before battle state changes. This does not alter normal save slots or golden outputs.
- Recovery launches now run startup first, restore the validated ledger and stage its board paused. The host can inspect recovery status and explicitly resume; board threads, entry instructions and item multitask threads wait until then. Changed or missing required board/entry assets refuse the launch without exposing partial recovered state. New candidates include required-asset fingerprints; older candidates without them are refused because asset compatibility cannot be established.


- Save restoration preserves object values and suspended method continuations after explicit release, including when a freed handle is reused by another class. Values retain a positive safe-integer handle and string class tag; comparisons continue to use handles. Object-member references and callable receivers still require live objects, and destructor continuations still require a live release handle.

- Load reports a saved program-reference compiler mismatch before validating a malformed schema or audio projection, and refuses malformed or dimension-mismatched surface base64 before committing restored state.

- Loading a battle save now warns when a fighter is on the wrong team. The entry stays in its original position and is skipped rather than silently fighting for the wrong side.

- The battle event contract is now regression-tested at its exact shape. The stock outcome test asserts that the actor-local `defeated` and its game-level `stock_battle.defeated` re-emission carry exactly the keys `cause` and `source`, with the attacking actor's id as the source; the authored no-stock custom fight program emits the same ruled detail and proves nothing re-emits it on the game; and the damage tests assert `beforeDamage`'s exact `source`, `target` and `damage` detail, that a listener's mutated amount is clamped at the owner's HP/SMP boundary, and that an item-origin action dispatches exactly one cancelable `beforeDamage`.
- A battle background whose picture is a tile bitmap (`.tbm`) now shows. The stock battle screen no longer blanks a `.tbm` background, and the engine turns the file's cells — each cell's tile with its tint — into one picture for `bitmap`, the `setimage*` family and a battle background, using the same tile readers boards already use. A `.tbm` whose tiles have not arrived yet keeps its draw queued until they do, and a broken cell is reported as an invalid asset instead of quietly leaving the flat colour. PNG, JPEG, BMP and GIF backgrounds keep their behaviour, and no golden frame changed.
- Battle participant statuses now end with the battle. Once the final outcome is selected, the core outcome adapter removes every status counter from both parties — enemies included — after that outcome's own handling, so the run, win and game-over programs still see the statuses recorded during the fight, and before it announces `battleEnded`. This covers the outcome codes the package or a custom program handles itself (1 and 3) as well as the automatic ones. Actors that took no part in the battle keep their statuses, a successful escape still lets later charged fighters of that pass tick their statuses first, and a party left at 0 HP by those ticks still loses instead of escaping.
- A battle's identifier is never handed out twice in one run. The number came from the live `battle` section, which loss cleanup clears before a game-over program runs, so a game-over program that started another battle received the first battle's number; the counter now lives in the saved `engine` section as `nextBattleId` (plain data, optional, no schema-version change). A save/restore continues a run's numbering, `reset()` starts a new run at 1, and a save written before the counter existed takes one past the active battle's `id`. A mid-battle save now carries the field, so `fixtures/save/battle-v2-mid.json` records it.
- The compiled-program cache remembers the program it answered for each reference object, so a repeated request no longer rebuilds that reference's cache key. An inline reference carries the whole program text and the VM asks for its frame's program on every instruction, so the battle rigs rebuilt an about 95 KB key per step. References are immutable, so a changed program still arrives as a new reference and compiles afresh, and each cache keeps its own memos, so separate caches and test rigs never share a compiled program. Measured on Node 24.21.0: the core-battle shard 108.8 s to 51.3 s, and 300 single-tick advances of a real battle 19.4 to 12.7 ms per tick.
- Battle UI refresh tests reuse one real battle per screen mode, restoring each changed value and checking its pixels before the next case. The six-tick refresh checks and duplicate-name pixel comparisons remain intact.
- Documented and tested how pre-vector boards handle oversized final tile runs: excess repetitions are discarded, following fields remain readable, and Reawakened warns about the overrun. The original applications did not issue that warning.
- Jensen approved the complete battle screen on 2026-10-28, including by-name revive targeting. It keeps the selected command visible while choosing a move, item, or target and highlights list entries across their column.
- Battle selection keeps the command label and active member name at exactly the same yellow; selected unavailable moves remain visibly dimmed with improved contrast, and the description header no longer exposes the background beneath its label.
- Using a stack in the battle Items list now spends that stack. Before, the "Special Potion" row spent the canonical "Potion" stack, and two non-canonical stacks of one item file healed the target but spent neither. `battleconsume` takes an optional stack `handle` (the `inventory.consume` request carries `handle`, `null` when none is named); the owner consumes exactly the named stack, and the battle screen checks the chosen stack still has a unit before it changes any stat.
- Loading a mid-battle save into a brand-new engine no longer fails to draw. The saved stance animations come back already loaded, so the engine now asks the host for their frame pictures on load, keeps each animation's saved frame and origin tick, and leaves an animation out of the drawn frame until its pictures have arrived instead of reporting `render.failed`.
- The battle UI cadence test now starts a real Fight and checks every fighter's own animation, frame and rendered pixel on every tick (idle and during the action) at 1-, 2- and 3-tick delays; one-tick-early and one-tick-late frames are rejected.
- The battle screen now redraws displayed fighter names, current and maximum HP and SMP, charge and fallen state within six ticks without another key press, idle or in any menu, while keeping one battle pass per tick. Golden draw-list hashes include the snapshot tick, so the merged redraw paths change them even when pixels match. Against the pre-merge golden, only `defeated.png` changes (charge-bar pixels at the recorded battle-loop step); the other four PNGs are unchanged.
- Battle menu redraws hide fighter pictures before publishing a list and restore them only after publishing its replacement, without restarting their animation timelines. Queued Escape presses keep the correct visibility through the intermediate list. Target-picker labels and the target message also refresh when a rename arrives with a cursor move, including changed duplicate-name suffixes.
- Not changed: custom logical resolutions below 640×480 still use the 640×480 layout numbers; this needs an owner decision (see the pull request).

- Script drawing (`setpixel`, `drawline`, `drawrect`, `fillrect`, `drawcircle`, `fillcircle`, `clear`, canvas blits) edits live pixel buffers kept outside saved state, and each command re-encodes only the span it can touch. Inside a thread phase the edits are held and written into the plain-JSON base64 snapshots when the phase ends, including after a thrown command or a debugger pause. Opaque, unscaled copies use clipped scanlines; translucent pixels keep their existing blend behavior, and a surface blitted onto itself reads its pre-blit pixels.
- Bounds are never narrower than what the draw routine can write: an infinite `fillrect` edge clips to the surface like the pixels it draws, and an unknown extent covers the whole surface. An unbounded edit is never narrowed by a later bounded one.
- Batching is off when effect appliers or script observers are installed, and stays on with a main file, package catalogue or phase registrations. Package, catalogue and main-file plugin code (commands, listeners, host-object member hooks and host-type emitter keys) is handed the state tree, so pending drawing is written out before any of it runs, and again when a layer it called through `next` returns; built-in commands never trigger that. Such code therefore sees exactly the snapshots eager drawing would give it, on the call and on any later callback that reads a retained view.
- Each surface keeps one indexed working buffer, so a batch that is closed no longer drops the buffer a newer batch took for the same surface state; two sections that reference one surface entry keep their own pixels until their own batch ends.
- State hashes remain the same FNV-1a hashes. Cached bitmap text avoids reserializing unchanged surface payloads, while per-block transitions can reuse exact hash work even when earlier state changes. Direct edits to bitmap text and metadata still invalidate the relevant cache.
- Canvas text uses the same batch-aware pixel writes as other surface drawing and reuses its raster-asset map; the surface hash cache also handles the render-now on/off flag without changing canonical hashes.
- Each block transition learns only the incoming low-byte value encountered during a hash. A different value requires another scan of that block, so one traversal does not prepare all possible values. The cache holds at most 2,048 blocks per game state: old blocks no longer in the current state are evicted first, and additional blocks use the ordinary hash path if all retained blocks are active. Cold, changing, or highly varied surfaces can still require substantial sequential hashing.
- Measured on Node 24.21.0 against `origin/main` (identical state hashes): 60 direct 640×480 drawing operations plus a complete state hash took about 2.5 s before and about 48–51 ms after in steady rounds (61–73 ms for the first, cold round); a frame of 60 `fillrect`s over four 640×480 canvases plus a hash took about 4.8 s before and about 88 ms (median) after; a tick that edits four high-entropy 640×480 surfaces while the state prefix changes took about 630 ms before and about 61 ms (median) after. The 50 ms budget for 60 direct 640×480 drawing operations plus a complete state hash is **not reliably met**: the cold first round exceeds it and steady rounds sit at its edge.
- Hashing shared inline program owners now reuses canonical fragments and lazily learned exact FNV transitions while checking each owner's current fields for direct edits. Non-ASCII, nested or unusually large owners use the ordinary hash path; newly encountered incoming byte lanes still need a full scan. The per-state cache retains at most 32 program fragments of at most 256 Ki characters each and discards inactive entries when full, so changing or varied workloads may receive less benefit.
